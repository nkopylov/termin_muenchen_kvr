# Bot Text and Translations

The bot speaks English and Russian. All user-facing text lives in message catalogs and is rendered with `t()`.

## Layout

- `src/i18n/__init__.py` – `t(key, lang, **params)`, plural rules, catalog merging.
- `src/i18n/user_language.py` – reads and stores a user's language.
- `src/i18n/locales/<lang>/<area>.py` – one module per bot area (`start`, `help`, `buttons`, `booking`, …), each with a `MESSAGES` dict. Every module must be listed in `AREAS` in `src/i18n/locales/<lang>/__init__.py`.
- Keys are `"<area>.<name>"`, e.g. `"setdates.updated"`. A key defined twice across areas raises at import time.

## Adding a message

1. Add the key to **both** `en/<area>.py` and `ru/<area>.py`.
2. Use named placeholders (`{date}`, `{count}`) and the same set in both languages.
3. Render it: `t("area.name", lang, date=...)`.
4. For counts, use a plural dict and pass `count=`:
   - en: `{"one": ..., "other": ...}`
   - ru: `{"one": ..., "few": ..., "many": ...}`, each form containing `{count}`.
5. Messages sent with `parse_mode="HTML"` must keep their tags balanced.

`tests/test_i18n.py` enforces key parity, placeholder parity, plural forms and HTML balance.

If a key is missing in Russian, `t()` logs a warning and falls back to English. An unknown key raises `KeyError`.

## Language resolution

- `User.language` stores `"en"`, `"ru"`, or `""` (not chosen yet).
- `get_user_language(user_id, context)` returns the cached value from `context.user_data["lang"]`, otherwise reads the DB. Unset or unknown values render as English and are not cached.
- `set_user_language()` writes the DB and the cache. `/language` and the menu's Language button show the picker; `lang:<code>` callbacks store the choice.
- `language_gate` (handler group -1) intercepts every update from a registered user whose language is unset, sends the picker and stops further handlers. The language flow itself (`/start`, `/language`, `language`, `lang:*`) passes through.
- Migration 1 in `src/database.py` resets every stored language to `""` once, tracked with `PRAGMA user_version`, so existing users are asked to choose.
- `set_default_commands()` publishes the Telegram command list in English, plus a Russian list for clients set to Russian. Choosing a language also sets that chat's command list.

Code that runs outside a handler (notifications, background checks) passes no context and reads the language from the DB.

## Not translated on purpose

- Data from the city API: service and office names stay German.
- German institution names (Ausländerbehörde, KVR, Bürgeramt) stay German in Russian text.
- Admin-only text: `/stats` output, `show_stats_inline`, health alerts. The `/stats` refusal shown to non-admins is translated.

## Russian terminology

"запись" for appointment, "подписка" for subscription, "период дат" for date range, "отделение" for office, lowercase "вы". The bot speaks in the first person singular ("я").
